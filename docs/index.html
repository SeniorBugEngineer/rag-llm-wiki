02

LLM 很厲害，但有三個老毛病

hallucination

幻覺

用很有自信的語氣，說出錯誤或沒有根據的內容。

outdated

知識過時

知識停在訓練資料的那一天，之後發生的事都不知道。

untraceable

無法追溯

說不出答案是從哪裡來的，使用者無從查證。

RAG 綜述把這三項列為 LLM 的主要挑戰。

03

原因：知識都「背」在參數裡

語言模型把讀過的知識壓縮存在參數中，論文稱為 parametric memory。這種記憶的問題是：

  • 難以精確取出特定事實
  • 無法指出答案的出處
  • 要更新知識，就得重新訓練
就像閉書考：只能靠記憶，記錯了也不知道。
04

一句話：先查資料，再回答

RAG 把閉書考，變成開書考。

parametric memory

模型參數裡的知識

原本就有的「記憶」，負責理解問題、組織語言。

non-parametric memory

可檢索的外部資料

一個可以隨時查詢、隨時替換的文件索引。

2020 年 Lewis 等人提出 RAG，把兩種記憶接在一起：外部資料用的是約 2,100 萬段 Wikipedia。

05

RAG 的三個步驟

1 · indexing（事先做好）

建索引

文件切成小段 → 每段轉成向量 → 存進向量資料庫。

→
2 · retrieval

檢索

問題也轉成向量，找出最相似的 top-K 段（也就是最像的前 K 段）。

→
3 · generation

生成

「問題＋找到的段落」一起交給 LLM 回答。

例子（示意）

問：「2018 年的英國首相是誰？」→ 檢索到一段寫著 2018 年英國首相的 Wikipedia 段落 → LLM 讀了這段再回答，而且可以附上出處。

綜述稱這個基本流程為 Naive RAG 的「Retrieve-Read」。

07

Chunking：先把文件切成小段

檢索找的是「段」，不是整份文件。常見做法是切成固定長度，例如 100 256 512 tokens。

大 chunk

上下文較完整，但雜訊多、成本高。

小 chunk

內容精準，但可能缺少理解所需的上下文。

折衷做法

Sliding window 重疊切；Small2Big 用句子檢索，再附上前後文。

  • DPR 用兩個 BERT：一個把問題轉成向量，一個把段落轉成向量。
  • 所有段落的向量事先算好，存進 FAISS 索引；查詢時只要算問題的向量。

10

陷阱一：chunk 斷章取義

某個 chunk 的全部內容

“The company's revenue grew by 3%”

  • 是哪一家公司？
  • 是哪一季？

切塊之後，chunk 失去了原文的上下文。使用者問「某公司第二季營收成長多少？」，這段就可能檢索不到。

12

Contextual Retrieval：替 chunk 補上背景

原本

“The company's revenue grew by 3%”

→
加上 LLM 寫的背景

這段出自某公司某季財報，前一季營收為… The company's revenue grew by 3%

  • LLM 讀整份文件後，為每個 chunk 寫 50–100 tokens 的背景說明。
  • 加了背景的 chunk，同時拿去建向量索引和關鍵字索引。
  • 一次性成本約每百萬文件 tokens 1.02 美元。

背景說明的文字是示意。

Self-RAG：自己決定要不要查，再自己檢查

Reflection token模型問自己可能的答案
Retrieve現在需要查資料嗎？yes / no / continue
IsRel這段資料和問題相關嗎？relevant / irrelevant
IsSup我的回答有被資料支持嗎？fully / partially / no support
IsUse這個回答有用嗎？5 ～ 1 分

PopQA 正確率：Self-RAG 13B 55.8，加檢索的 ChatGPT 50.8。但不是每項都贏：長文引用的 recall 仍低於加檢索的 ChatGPT。

RAGAS：分開檢查「找資料」和「寫答案」

faithfulness · 0.95

答案有沒有亂講？

把答案拆成多句陳述，算出被檢索內容支持的比例。

answer relevance · 0.78

有沒有答到問題？

從答案反推問題，比較它和原問題有多像。

context relevance · 0.70

找到的資料精準嗎？

真正需要的句子，占檢索內容的比例。

RAGAS 不需要人工標準答案。卡片上的數字，是它與人工判斷的一致率。

18

總結

  • 先查再答：RAG 用外部資料補上幻覺、過時、無法追溯三個問題。
  • 切塊與向量：文件切成 chunk，轉成 embedding，找最相似的幾段。
  • 注意擺放：給太多、放中間，模型反而會漏看。
  • 加背景、混合檢索、rerank：改良的效果可以疊加。
  • 分開評估：檢索好不好、答案忠不忠實，要分別量測。

自我檢測

Q1．為什麼答案放在中間，反而比不給資料還差？

模型最注意上下文的開頭和結尾。GPT-3.5-Turbo 在答案放中間時只答對 53.8%，低於閉卷的 56.1%。

Q2．BM25 和向量檢索各擅長什麼？

BM25 擅長字面精準比對（例如專有名詞）；向量檢索擅長同義改寫。兩者結合就是 hybrid search。

Q3．Faithfulness 在量什麼？

答案中有多少比例的陳述，能被檢索到的內容支持，也就是答案有沒有「亂講」。
